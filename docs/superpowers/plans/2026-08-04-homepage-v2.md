# Homepage v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the homepage to the visual standard of the Digital Silk homepage — depth, large-format imagery, editorial composition — without changing a single ranking string, and without regressing Core Web Vitals.

**Architecture:** New sections live in `components/home2/`, composed by one `HomeV2` component and previewed at a noindex `/home-v2` route. `components/home/` and `content/home.ts` are never modified — the redesign *imports* the parity-locked copy rather than copying it. Promotion is a one-line import change in `app/(site)/page.tsx`; reversion is the same line changed back.

**Tech Stack:** Next.js 16.2.12 (App Router, Turbopack), React 19.2, TypeScript strict, Tailwind v4 (CSS-first, `@theme` in `app/globals.css`). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-04-homepage-v2-design.md`

## Global Constraints

Every task's requirements implicitly include this section.

- **Never modify `components/home/` or `content/home.ts`.** They are the revert target. If a task appears to need a change there, stop and escalate.
- **No new dependencies.** No animation, carousel, or icon library. `package.json` must be unchanged at the end of this plan.
- **Server Components by default.** Add `"use client"` only for genuinely interactive components, and prefer reusing the existing client components (`Rail`, `Counter`, `Reveal`, the tablist) over writing new ones.
- **Every image through `next/image` with explicit `width` and `height`.** Decorative images get `alt=""` and `aria-hidden="true"`.
- **`<Image priority>` is deprecated in Next 16** — use `preload`.
- **4-space indent** (`.editorconfig` wins over the mostly-2-space existing files).
- **One container:** `container-site`. Full-bleed backgrounds are absolute layers *behind* the container, never a second container token.
- **Additive CSS only.** All new `globals.css` content goes inside a single fenced `/* ==== home-v2 ==== */ … /* ==== end home-v2 ==== */` block at the end of the file. Never redefine an existing token or utility.
- **No `Review` / `AggregateRating` structured data** — see `docs/SEO-PLAYBOOK.md`.
- **Reduced motion:** every new animated effect must collapse under `prefers-reduced-motion: reduce`.
- **This project has no unit-test runner.** Its established verification idiom is: `npx tsc --noEmit`, `npm run lint`, `npm run build`, the Python parity scripts, and `scripts/audit-responsive.mjs` over CDP. Follow it. Do **not** introduce vitest/jest — that is unrequested scope.
- **Responsive floor is 320px.** Every section must be verified there, not just at desktop.
- Commit after every task.

- [ ] **Step 1: Append the token block to `app/globals.css`**

Add at the very end of the file:

```css
/* ==========================================================================
   ==== home-v2 ====

   Additive block for the homepage redesign (components/home2/). Everything
   here is a NEW name — nothing above is redefined — so the whole block can be
   deleted to revert the redesign without touching the rest of the file.

   See docs/superpowers/specs/2026-08-04-homepage-v2-design.md
   ========================================================================== */

@theme {
    /* Oversized step numerals (01 02 03). Deliberately above --text-display:
       these are graphic elements, not headings, and they set the editorial
       scale the whole redesign hangs off. */
    --text-numeral: clamp(3.5rem, 1.5rem + 9vw, 9rem);
    --text-numeral--line-height: 0.85;
    --text-numeral--letter-spacing: -0.05em;

    /* A wider glow than --shadow-glow, for large focal surfaces (the featured
       work frames, the hero form card) where the tighter one disappears. */
    --shadow-glow-lg: 0 40px 120px -30px rgb(204 6 127 / 0.55);

    /* Vertical rhythm for full-bleed interstitial bands — tighter than
       --spacing-section, because a band is a punctuation mark, not a section. */
    --spacing-band: clamp(2.5rem, 1.5rem + 4vw, 4.5rem);
}

/* Frosted surface: blur + hairline + an inner top highlight. The highlight is
   what stops the card reading as flat translucent grey — it simulates a light
   source above the surface, which is the whole trick behind this style. */
@utility glass {
    background-color: rgb(255 255 255 / 0.04);
    backdrop-filter: blur(16px);
    box-shadow:
        inset 0 1px 0 0 rgb(255 255 255 / 0.14),
        inset 0 0 0 1px rgb(255 255 255 / 0.09),
        var(--shadow-lg);
}

/* Radial brand bloom, for placing behind a focal element. Always on a
   pointer-events-none, aria-hidden layer. */
@utility glow-bloom {
    background-image: radial-gradient(
        closest-side,
        rgb(204 6 127 / 0.45) 0%,
        rgb(102 46 145 / 0.25) 45%,
        transparent 100%
    );
}

/* Hairline grid that fades out downward — sits under editorial dark bands to
   give them structure without competing with the mesh. */
@utility bg-grid-fade {
    background-image:
        linear-gradient(rgb(255 255 255 / 0.05) 1px, transparent 1px),
        linear-gradient(90deg, rgb(255 255 255 / 0.05) 1px, transparent 1px);
    background-size: 72px 72px;
    mask-image: linear-gradient(180deg, #000 0%, transparent 75%);
}

/* ==== end home-v2 ==== */
```

Same marquee mechanics, restyled for its new position: on the dark canvas directly under the hero rather than a white band, so the marks are knocked out to white with `brightness-0 invert` (the artwork is dark-on-transparent — see the note in `content/clients.ts`), at reduced opacity, lifting to full on hover.

```tsx
import Image from "next/image";

import { clientMarquee, clients } from "@/content/clients";

/**
 * Client logo marquee (v2).
 *
 * Moved from sixth on the page to second — a trust wall directly under the
 * hero. Mechanically identical to components/home/Logos.tsx: the track is
 * duplicated and translated by exactly -100% minus the gap, which loops with
 * no JS, and each pass repeats the list `copiesPerPass` times so the laid-out
 * track always exceeds the viewport.
 *
 * Only the first copy of the first pass carries alt text; every later copy is
 * decorative, so screen readers and crawlers see each logo exactly once.
 *
 * The artwork is dark-on-transparent, so on this dark band it is knocked out
 * to white rather than shown as-is.
 */
export default function Logos() {
    const copies = Array.from({ length: clientMarquee.copiesPerPass }, (_, c) => c);

    return (
        <section
            className="relative isolate overflow-hidden border-y border-white/[0.08] bg-ink-950 py-band"
            aria-label={clientMarquee.label}
        >
            <div className="pointer-events-none absolute inset-0 z-0 bg-noise opacity-30 mix-blend-overlay" aria-hidden="true" />

            <p className="relative z-[1] mb-8 text-center text-xs tracking-[0.16em] text-white/35 uppercase">
                {clientMarquee.label}
            </p>

            <div className="relative z-[1] flex mask-edges">
                {[0, 1].map((pass) => (
                    <div
                        key={pass}
                        className="flex min-w-full shrink-0 animate-marquee items-center gap-[--marquee-gap] [--marquee-gap:4rem] hover:[animation-play-state:paused]"
                        aria-hidden={pass === 1 ? "true" : undefined}
                    >
                        {copies.map((copy) =>
                            clients.map((client) => {
                                const announced = pass === 0 && copy === 0;
                                return (
                                    <Image
                                        key={`${pass}-${copy}-${client.name}`}
                                        src={client.src}
                                        alt={announced ? client.name : ""}
                                        aria-hidden={announced ? undefined : "true"}
                                        width={client.width}
                                        height={client.height}
                                        className="h-[clamp(2rem,1.6rem+1.2vw,2.75rem)] w-auto shrink-0 opacity-45 brightness-0 invert transition-opacity duration-300 hover:opacity-100"
                                    />
                                );
                            }),
                        )}
                    </div>
                ))}
            </div>
        </section>
    );
}
```

### Task 10: The parity gate

Closes a real pre-existing gap: the 36 service pages and all 4 landing pages are parity-gated; **the homepage is not**. This asserts mechanically the claim the whole redesign rests on.

**Files:**
- Create: `scripts/verify-home-v2-parity.py`
- Modify: `AGENTS.md` (add the script to the verification command list)

**Interfaces:**
- Consumes: `content/home.ts`, a rendered `/home-v2` HTML file
- Produces: exit code 0 on pass, 1 on failure with the missing strings listed

- [ ] **Step 1: Read an existing parity script for the house style**

```bash
head -60 scripts/verify-landing-parity.py
```

Match its argument handling, output format and exit codes.

- [ ] **Step 2: Write `scripts/verify-home-v2-parity.py`**

It must:

1. Extract every string literal from `content/home.ts` (the double-quoted and backtick-quoted values, skipping keys, comments, and paths beginning `/assets/`).
2. Read the rendered `/home-v2` HTML.
3. Unescape HTML entities and normalise whitespace on both sides before comparing — `&amp;`, `&#x27;`, and curly quotes will otherwise produce false failures. Note that `content/home.ts` already uses curly apostrophes (`’`) deliberately; do not normalise those away, normalise the *HTML* to match.
4. Fail with a non-zero exit and print every string that is missing.

Skip these keys, which are asset paths or numeric values rather than prose: `img`, `icon`, `src`, `art`, `bg`, `frame`, `shot`, `image`, `mark`, `orbitIcons`, `value`, `suffix`, `href`.

- [ ] **Step 3: Run it against the CURRENT homepage first, to prove the script works**

This is the critical step — a parity script that passes trivially is worse than none.

```bash
node scripts/capture-rendered.mjs http://127.0.0.1:3100/ /tmp/home-v1.html
python scripts/verify-home-v2-parity.py /tmp/home-v1.html
```

Expected: **PASS**. The v1 homepage renders all of `content/home.ts` by definition, so a failure here means the script's extraction or normalisation is wrong — fix the script, not the page.

- [ ] **Step 4: Prove it actually fails when copy is missing**

```bash
python - <<'PY'
import re
html = open('/tmp/home-v1.html', encoding='utf-8').read()
# drop the hero sub-heading
open('/tmp/home-broken.html','w',encoding='utf-8').write(
    html.replace('Every day you wait is an opportunity they take.', '', 1))
PY
python scripts/verify-home-v2-parity.py /tmp/home-broken.html
```

Expected: **FAIL**, naming the removed string, exit code 1. If it passes, the script is not actually checking anything — fix it before continuing.

- [ ] **Step 5: Run it against `/home-v2`**

```bash

python scripts/verify-home-v2-parity.py /tmp/home-v2.html
```

Expected: **PASS**. Any failure here is dropped copy in the redesign — fix the component, never the script.
